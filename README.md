# authfly/codegen

Code generation for the Authfly UI layer, in the 9 targets of UI8Kit: **React 19 · Vue 3 · Svelte 5 · SolidJS ·
Web Components** and the server-side template engines **Go templ · Twig · Latte · Jinja2**.

Same approach as [ui8kit/codegen](https://github.com/ui8kit/codegen) (one typed spec → one emitter per target →
parity tests), one level up: ui8kit/codegen generates the primitives (Box, Button, Input, …, published as
`@ui8kit/registry`); this repo generates what Authfly builds from them. Primitives are never copied here: generated
code imports them from the target's `ui/` folder, and the brand registry lists them as pinned URLs of
`@ui8kit/registry@3.3.0`.

| command | source | output (in an [authfly/authkit](https://github.com/authfly/authkit) checkout) |
| --- | --- | --- |
| `shared` | `packages/shared/src` (skin recipes, widget types, Lucide glyphs, theme) | byte copies in the 5 JS targets; Go / PHP / Python tables for templ, Twig, Latte, Jinja2 |
| `widgets` | `specs/widgets/*.def.ts` (this repo) | the widget source in all 9 targets |
| `components` | `specs/components/*.def.ts` (this repo) | the Authfly middle layer: one file per component in React, Solid, Vue, Svelte, Web Components, templ; a `codegen:begin/end <name>` region in the Twig / Latte / Jinja2 `authfly/components.*` macro file |
| `registry` | `packages/ui/<rt>` | `packages/registry/src/<rt>/registry.json` (brand registry manifests) |

```sh
bun src/cli.ts <shared|widgets|components|registry|all> [--check] --root <authkit>
scripts/publish-registry.sh <ui8kit-site-checkout> [authkit]   # build + copy into ui8kit/site r/authfly/ (no push)
```

authkit pins this repo in `deps.lock` and runs it through `tools/codegen.sh` (CI: `tools/codegen.sh all --check`);
parity (20 states × 9 targets), HTML/ARIA gates, ui8px lint and `ui8kit check` run in authkit's CI.

## Widget specs

`src/dsl.ts`: expressions (`prop`, `lab` = labels key, `item`, `eq`, `iff`, `cat`) and nodes for the Authfly middle
layer (`head`, `messages`, `stack`, `form`, `field`, `hidden`, `button`, `submit`, `link`, `foot`, `icon`, `text`)
plus `when` / `each`. Emitters: `src/emit/js.ts` (React, Vue, Svelte, Solid), `wc.ts`, `templ.ts`, `server.ts`
(Twig, Latte, Jinja2). Generated files start with `Code generated by authfly/codegen … DO NOT EDIT.`

Status: all six widgets (**sign-in**, **sign-up**, **request**, **notice**, **consent**, **account**) are generated
in all 9 targets. DSL growth per widget: sign-up `checkbox`, `field` `hint` / `addon` (templ: `addonInput` in authkit
`blocks.templ`); request `orv`, `field` `inputmode`; notice `iconBadge`, `para`, `head` align/role/kids, `when`
`els` / `inline`, `form` action/extra/errorId, widget `card` and `lets` / `local()`; consent and account `el` (Box /
Text with a tag, token classes or the muted skin), `title`, `badge`, `separator`, `group`, `sp`, `each` `as` +
`item(field, var)`, `button` `type`, `form` `testid`, boolean props. 

Middle layer (`src/dsl-components.ts`, `src/components.ts`, templates per kind in `src/emit/components.ts`):
**Card** (kind `surface`), **Alert** (kind `message`), **Badge** + **IconBadge** (kind `pill` with its `tile`),
**Title** (kind `heading`), **LucideIcon** (kind `glyph`, server macro `icon`) and the layout (kind `layout`: Stack,
Group, Form, Vue/Svelte `layout.ts` tables, server `box` / `text` wrappers) are generated. Still hand-written in
authkit: Field (+ form-error context), Hidden, WidgetHead/Messages/_parts, props, Jinja2 `prim`, the server
field/head/messages macros and the templ helpers; next: specs for those.
